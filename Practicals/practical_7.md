# ПР №7

## 

| VLAN 1 | VLAN 2 | мережа VLAN 1 | мережа VLAN 2 | порти комутатора |
|---|---|---|---|---|
| 15, FIN | 25, QA | 192.168.15.0/24 | 192.168.25.0/24 | fa0/1 -> VLAN15, fa0/2 -> VLAN25 |

по два ПК на кожну VLAN, тому додатково fa0/3 -> VLAN15 і fa0/4 -> VLAN25

## 2

налаштування комутатора

```
enable
configure terminal
hostname SW1

vlan 15
 name FIN
vlan 25
 name QA
exit

interface range fa0/1, fa0/3
 switchport mode access
 switchport access vlan 15

interface range fa0/2, fa0/4
 switchport mode access
 switchport access vlan 25

interface gig0/1
 switchport mode trunk
end
write memory
```

![21task](https://github.com/HaxDP/KMS/blob/master/Photos/PR7/pr7_21.png)

перевірка

```

```

```
15   FIN        active    Fa0/1, Fa0/3

```
![22task](https://github.com/HaxDP/KMS/blob/master/Photos/PR7/pr7_22.png)

IP-адреси на ПК лишаються з 192.168.1.0/24

| ping | результат |
|---|---|
| ПК1 -> ПК3, обидва VLAN 15 | працює, 4 відповіді з 4 |
| ПК2 -> ПК4, обидва VLAN 25 | працює, 4 відповіді з 4 |
| ПК1 -> ПК2, VLAN 15 і VLAN 25 | не працює, Request timed out |
| ПК3 -> ПК4, VLAN 15 і VLAN 25 | не працює, Request timed out |

чому між VLAN не працює

порти різних VLAN належать різним широкомовним доменам, і комутатор не пересилає кадри з однієї VLAN в іншу

ARP-запит ПК1 про адресу 192.168.1.2 є широкомовним, тому доходить лише до портів VLAN 15, а ПК2 у VLAN 25 його не отримує

MAC-адресу ПК2 дізнатися неможливо, тому ping не проходить, хоча IP-адреси в одній підмережі

## 3

налаштування маршрутизатора

```
enable
configure terminal
hostname R1

interface g0/0
 no shutdown

interface g0/0.15
 encapsulation dot1Q 15
 ip address 192.168.15.1 255.255.255.0

interface g0/0.25
 encapsulation dot1Q 25
 ip address 192.168.25.1 255.255.255.0
end
write memory
```

![3task](https://github.com/HaxDP/KMS/blob/master/Photos/PR7/pr7_31.png)

перевірка

```
show ip interface brief
```

![32task](https://github.com/HaxDP/KMS/blob/master/Photos/PR7/pr7_32.png)

мають бути інтерфейси g0/0.15 з адресою 192.168.15.1 і g0/0.25 з адресою 192.168.25.1 у стані up

субінтерфейси сидять на одному фізичному порту g0/0, який з'єднаний із транковим портом gig0/1 комутатора, і кожен із них обслуговує одну VLAN за тегом IEEE 802.1Q

## 4

нові адреси ПК за мережами варіанта

| вузол | VLAN | IP-адреса | маска | шлюз |
|---|---|---|---|---|
| ПК1 | 15 | 192.168.15.10 | 255.255.255.0 | 192.168.15.1 |
| ПК3 | 15 | 192.168.15.11 | 255.255.255.0 | 192.168.15.1 |
| ПК2 | 25 | 192.168.25.10 | 255.255.255.0 | 192.168.25.1 |
| ПК4 | 25 | 192.168.25.11 | 255.255.255.0 | 192.168.25.1 |

| ping | результат |
|---|---|
| ПК1 -> 192.168.15.1, шлюз | працює |
| ПК1 -> ПК3 | працює |
| ПК1 -> ПК2, 192.168.25.10 | працює, відповіді з TTL=127 |
| ПК3 -> ПК4, 192.168.25.11 | працює, відповіді з TTL=127 |

перший пакет першого ping між VLAN може загубитись через ARP, наступні проходять

TTL=127 замість 128 показує що пакет пройшов через маршрутизатор

що змінилось

до маршрутизатора вузли різних VLAN не мали спільного шару 3, і комутатор рівня 2 не маршрутизує трафік між VLAN

тепер ПК1 бачить, що адреса 192.168.25.10 з іншої підмережі, і відправляє кадр на MAC-адресу шлюзу 192.168.15.1

маршрутизатор приймає кадр з тегом 15 на субінтерфейсі g0/0.15, дивиться в таблицю маршрутизації і відправляє пакет назад через субінтерфейс g0/0.25 з тегом 25

комутатор доставляє кадр до ПК2 в VLAN 25

## висновок

VLAN розділили комутатор на два незалежні широкомовні домени, тому вузли FIN і QA не бачили одне одного навіть на одному комутаторі

зв'язність з'явилась лише після додавання маршрутизатора, бо тільки пристрій рівня 3 з субінтерфейсами може передати трафік між VLAN

для цього кожна VLAN отримала шлюз на субінтерфейсі, а на ПК цей шлюз був прописаний
